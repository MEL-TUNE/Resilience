# 手元のAI（このパソコンで動かすAI）でリオと掛け合いをする手引き

対象：配信処オトノハ STUDIO 0.11.3 以降の「リオと掛け合い」（準備 →「🎧 AIキャラ・声」）
書いた日：2026年11月18日（Ollama・LM Studio の画面や名前は、この日に調べた範囲のものです。変わっていることがあります）

## 何ができるか

オトノハの「リオと掛け合い」が、返事を作るのに、このパソコンの中で動くAI（Ollama か LM Studio）を使えます。

- APIキーも料金も要りません。会話の中身はパソコンの外へ出ません。
- 速さはパソコンの力で決まります。古いパソコンでは、1回の返事に数秒〜1分ほどかかることがあります（確かめていません。下の「目安」を参照）。
- 返事の上手さは、Claude や ChatGPT より落ちます。小さいモデルほど、口調が崩れたり、話がずれたりしやすくなります。
- 使えるのは、パソコンのブラウザ（Chrome・Edge）で開いたオトノハです。iPhone・iPad からは使えません（AI がパソコンの中にいるため）。
- claude.ai の「彼岸リオ 会話室」からは使えません（会話室のページは、外の場所へつなげない決まりで動いているため）。会話室は Claude が返事を書きます。

## はじめに：パソコンの空きメモリを見る

Windows：タスクマネージャー（Ctrl＋Shift＋Esc）→「パフォーマンス」→「メモリ」。「利用可能」がいまの空きです。
配信中は OBS とブラウザも動くので、その状態での空きを見てください。

| 配信中の空きメモリ | 試すモデル（Ollama の名前） | 大きさの目安 |
| --- | --- | --- |
| 2GB 未満 | 手元のAIはおすすめしません。Claude・ChatGPT か手渡しを | ― |
| 2〜4GB | qwen3.5:2b、gemma3:1b | 1.5〜2GB 前後 |
| 4〜6GB | qwen3:4b、qwen3.5:4b、gemma3:4b | 3GB 前後 |
| 8GB 以上 | gemma4:e2b、gemma4:e4b も候補 | 5〜10GB |

- 大きさは、モデルを読み込んだときに使うメモリのおおよそです。Ollama の一覧（ollama.com/library）にある数字を見て決めてください。
- 日本語のキャラクター会話では、Qwen（qwen3・qwen3.5）と Gemma（gemma3・gemma4）が候補になります。どれが一番リオらしく話せるかは、実際に試すまで分かりません。
- 「thinking（考える）」のあるモデル（qwen3 系など）は、答える前に考える分だけ遅くなります。オトノハは qwen3 系には考えを省く合図（/no_think）を付けて送り、考えた途中の文（<think>…</think>）は字幕から外します。新しい qwen3.5 でこの合図が効くかは確かめていません。遅いときは gemma3 を試してください。

## Ollama の場合（おすすめ。画面を開かずに動きます）

1. **入れる**：ollama.com/download から Windows 版を入れます。入れると、画面右下（タスクトレイ）に Ollama のアイコンが出て、裏で動き続けます。
2. **モデルを入れる**：スタートメニューで「PowerShell」を開き、次を打って Enter。
   `ollama pull qwen3:4b`
   （初回は数GB を落とすので時間がかかります。終わったら `ollama list` で入ったものが見られます）
3. **試しに話す**：`ollama run qwen3:4b` と打つと、その場で会話できます。返事の速さをここで見ておくと、配信で使えるかの判断になります。終えるときは `/bye`。
4. **オトノハから呼べるようにする**：PowerShell で次を打って Enter（1回だけ）。
   `setx OLLAMA_ORIGINS "https://mel-tune.github.io"`
   そのあと、タスクトレイの Ollama のアイコンを右クリック →「Quit Ollama」で終了し、スタートメニューから Ollama をもう一度起動します（設定は起動し直したときに読まれます）。
5. **オトノハでつなぐ**：準備 →「🎧 AIキャラ・声」→「つなぎ方」で「手元のAI（Ollama・LM Studio）にそのまま送る」を選びます。
   「Claude・ChatGPT・手元のAI とのつなぎ方」を開き、場所は `http://localhost:11434`、モデルの名前は 2. で入れたもの（例：`qwen3:4b`）にします。
6. **つながるか試す**を押します。Chrome・Edge が「ローカル ネットワーク上のデバイスを検出して接続する」などと尋ねたら「許可」を押します。「つながりました」と出れば準備完了です。

## LM Studio の場合（画面でモデルを選びたいとき）

1. lmstudio.ai から入れます。
2. 画面の検索でモデル（例：Qwen3 4B、Gemma 3 4B）を探し、ダウンロードします。迷ったら量子化は「Q4_K_M」を選びます（小さくて質が落ちにくい形式）。
3. 「Developer」（開発者）の画面でモデルを読み込み、サーバーを起動します。サーバーの設定で「Enable CORS」（CORS を有効にする）をオンにします。
4. オトノハの「つなぎ方」で、場所を `http://localhost:1234`、モデルの名前を LM Studio に表示されている名前（例：`qwen3-4b`）にして、「つながるか試す」を押します。
   LM Studio は、画面を開いてサーバーを起動している間だけ使えます。

## 配信で使うときの軽くするこつ

- **返事の長さの上限**を「短め（速い）」にします。字数が半分なら、待ち時間もおおよそ半分です。
- **「依頼文に添える会話の数」**を少なくします（手元のAIへ送るときも、この数だけ直近の会話を添えます）。送る文が短いほど、返事を作り始めるまでが速くなります。
- **使わないときは止める**：Ollama は最後に使ってから5分ほどでモデルをメモリから外します（標準の動き）。すぐ空けたいときは PowerShell で `ollama stop qwen3:4b`。
- 歌枠のときは使わない、と決めておくのが確実です。AI が返事を作っている間は CPU を強く使うので、OBS の映像がカクつくことがあります。
- 返事が遅すぎるときは、モデルを一段小さくします（4b → 2b → 1b）。

## うまくいかないとき

| オトノハに出る文 | 確かめること |
| --- | --- |
| つながりませんでした | Ollama・LM Studio が動いているか（Ollama はタスクトレイにアイコン）。ブラウザの「ローカルネットワーク」の許可を「ブロック」にしていないか（アドレス欄の左のアイコン → サイトの設定）。場所の番号（11434・1234）が合っているか |
| このページからの呼び出しが許されていません（403） | Ollama：OLLAMA_ORIGINS を入れたあと Ollama を起動し直したか。LM Studio：Enable CORS がオンか |
| モデル「…」が見つかりません | 名前が `ollama list` と一字一句同じか。`ollama pull` を済ませたか |
| 3分たっても返事がありませんでした | モデルが大きすぎます。一段小さくするか、返事の長さを短めに |
| 返事が変・口調が崩れる | 小さいモデルの限界のことが多いです。人格・口調の文を短く具体的にすると、少し良くなる場合があります |

## 安全のための注意

- OLLAMA_ORIGINS に `*`（どこからでも）を入れる手順をよく見かけますが、そうすると、開いた別のサイトからも手元のAIを呼べるようになります。上の手順のように、オトノハの場所（https://mel-tune.github.io）だけを書くほうが安全です。
- 手元のAIは、オトノハから送られた人格・口調・会話・あなたの発言だけを受け取ります。保存はしません（Ollama・LM Studio の標準の動き。ログの設定を変えた場合を除く）。
