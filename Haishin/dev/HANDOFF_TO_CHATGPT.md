## 1. このアプリについて

配信者・VTuber向けの、ブラウザだけで動く配信・収録アプリです。主な機能は次のとおりです。

- **音のお品書き**：効果音・ボイス・環境音・BGMのポン出し
- **ステージ**：PNGTuber（口パク・まばたき・表情差分・動き）、マスコット、背景、季節の演出
- **場面**：準備中・離席中・配信終了の画面、OBS 用の配信用ウインドウ、動画の収録
- **企画卓**：セリフ帳、スロット（役柄×セリフ）、ルーレット、サイコロ、企画のポン出し、外部 HTML アプリの登録（Otonoha Bridge 1 で連携）、AI観客席（手渡し方式）
- **歌枠ノート**：曲リスト（カラオケ音源の URL）、セトリ、歌唱の記録、概要欄、歌枠管理シート（Google スプレッドシート）との連携
- **AIキャラ・声**：ボイス録り（学習用の WAV・ZIP）
- **名義**（プロフィール）：キャラクター・マスコット・背景などを名義ごとに分けて持つ
- **すべての書き出し・読み込み（.live）**：設定・画像・アプリの HTML などを1つのファイルで持ち運ぶ

サーバーはありません。データはすべて、そのブラウザの IndexedDB と localStorage に置きます。

## 2. 絶対に守ること

1. **画像の左右反転は禁止。** 立ち絵・マスコット・背景・場面の画像・降らせる画像を、左右（上下）に反転させないでください。`scale(-1, 1)` などの負の倍率も禁止です。作者の強い要望です。
2. **画像を歪ませるのも禁止。** 画像は、移動・回転・縦横同じ倍率の拡大縮小だけです。`ctx.scale(x, y)` で x と y を変えること、`drawImage` で幅と高さを違う倍率にすること、CSS の `object-fit: fill` も使いません。縮めるときは縦横の比を必ず保ってください。
3. **保存キーの名前を変えない。** localStorage や IndexedDB のキー（`kissa` を含むものもあります）を変えると、利用者のデータが読めなくなります。
4. **.live の形を壊さない。** これまでに書き出した .live を読み込めるようにしてください。
5. **映像の向きの寸法を決め打ちしない。** 向きは `landscape`（1280×720）、`portrait`（720×1280）、`x34`（3:4、960×1280）の3つです。寸法は `W`・`H` から計算してください。
6. **Otonoha Bridge 1 の約束事を変えない。** これは外部アプリとの `postMessage` の決まりで、第三者のアプリも使う前提です。命令の種類・出来事の名前・許可の仕組みを変えないでください。
7. **歌枠管理シートのつなぎ先（URL と合言葉）を、設定の書き出し（.live）に入れない。** 今は localStorage の `otonoha-sheet-link` だけに置いています。

## 4. HTML の中の構造

`index.html` には `<script>` が大きく2つ入っています。

- **音声側**：ページ全体で共有する普通のスクリプトです。効果音の設定 `cfg`、`playSound`、`persist`、`toast`、.live の全体（`exportLive`）などがあります。
- **映像側**：1つの即時関数 `(()=>{ … })()` の中です。ステージ・企画卓・歌枠ノートなどは、すべてここにあります。

### 注意すべき仕組み

- 映像側の中では、`function` で書いた関数は、どこからでも呼べます（巻き上げられるため）。
- `const`・`let` は、定義より前に動く処理から使うとエラー（TDZ）になります。設定の読み込み（`sanitize`）は早い段階で動くので、そこから使う定数は関数の中に置いてあります。
- 音声側にも映像側にも `save` という名前の関数があります。映像側の中では、映像側の `save`（設定の保存）が使われます。

### 主な関数と役割（映像側）

| 機能 | 関数・変数 |
| --- | --- |
| 設定の初期値と保存 | `defaults`, `state`, `save()`（まとめて保存）, `saveNow()`（すぐ保存） |
| 設定の点検 | `sanitize(v)` ※新しい設定の項目を増やしたら、ここにも必ず足す。足さないと、読み込み直したときに消えます |
| 名義・キャラクター | `curProfile()`, `curChar()`, `syncChar()`（state → キャラ）, `activateChar()`, `activateProfile()`, `CHAR_KEYS`, `CHAR_RANGES` |
| 映像の向き | `applyAspect()`。向きごとの位置の記憶は `aspectStash()`, `aspectRestore()`, `charPosKeep()`, `aspectPosClean()` |
| 立ち絵の描画 | `avatarGeom()`（位置と大きさ）, `avatarPose()`（動き）, `drawAvatar(now, talking, blink, ctx, view)` |
| マスコット | `drawMascots()`, `myMascots()` |
| 毎フレーム | `frame()`。順番：背景 → 演出（奥） → マスコット → 立ち絵 → 場面の画像 → 演出（手前） → 字幕・セリフ・セトリ → AI観客席 → 各ウインドウへ写す |
| 背景画像 | `renderBgList()`, `bgCur()`, `bgImage()` |
| セリフ・ルーレット・サイコロ | `drawPlays()`, `drawSerif()`, `drawDice()`, `drawWheel()` |
| スロット・ルーレット・サイコロの位置と大きさ | `playPlace()`, `playLayGet()`, `playLaySet()` |
| スロット | `slotSpin()`, `drawSlot()`, `slotPal()`（色）, `slotPlan()`・`slotApply()`（JSON の取り込み） |
| 企画のポン出し | `renderPon()`, `ponRun()` |
| お題帳 | `state.topics`、`topicPrompt()`, `topicParse()`, `topicShow()`, `topicNext()`, `drawTopic()`, `renderTopicHand()`, `topicSanitize()` |
| 外部アプリ | `appShow()`, `appWinBtn`, `appCharDraw()`, `appLayerDraw()`（キャラクターだけの透過表示） |
| 連携 | `bridgeEmit()` と、`message` の受け口 |
| 歌枠ノート | `sing()`, `renderRep()`, `okeNorm()`（URL を整える）, `sheetCall()`, `sheetImport()` |
| .live の映像側 | `studioCollect()`, `studioApply()` |
| ドラッグ | `stagePoint()` と、`pointerdown`・`pointermove` のイベント（「✋ ドラッグで動かす」か「その場で調整」が開いているときだけ動かせる） |

### データの持ち方

- **名義**：`state.profiles[]`。キャラクター、場面、背景の種類、背景画像（`bgs[向き]`, `bgSel[向き]`）などを持ちます。
- **キャラクター**：`state.chars[id]`。画像、口パク、動き、位置と大きさを持ちます。
  - いまの向きの値は `x`, `y`, `scale`。向きごとの控えは `pos[向き]` です。
  - 範囲は横 -300〜300、縦 -200〜500、大きさ 10〜500 です。
- **マスコット**：`state.mascots[]`。位置・大きさ・傾き（いまの向きの値と `pos[向き]`）、動き、持ち主の名義を持ちます。
- **スロット・ルーレット・サイコロの位置**：`state.playLay[向き][slot|wheel|dice] = {x, y, s}`。
- **画像・アプリの HTML・動画**：IndexedDB の assets に別に置きます（`visual-studio:…`, `app:…`, `video:…`）。

## 5. 0.9.5 で直したこと（直前の作業）

- **読み込み直すたびに立ち絵の位置が変わる不具合**：0.9.4 で入れた「向きごとの位置の記憶」が、位置を ±100 の範囲に切り詰めていたのが原因でした。範囲を、設定のつまみと同じ（横 ±300、縦 -200〜500）に直しました。
- **ドラッグ**：ステージに「✋ ドラッグで動かす」のボタンを追加しました。オンのあいだは、立ち絵・マスコット・スロット・ルーレット・サイコロを、プレビューの上でドラッグして動かせます。
- **スロット・ルーレット・サイコロの位置と大きさ**：横・縦・大きさを細かく決められるようにしました。映像の向きごとに覚えます。
- **スマホの表示**：表情差分の編集欄で、入力欄が枠からはみ出していたのを直しました。ステージの「表情・キャラ・立ち絵の動き・話者」を色の付いたまとまりに分け、ポン出しと見分けやすくしました。

## 5-2. 0.9.6 で取り込んだこと（0.9.5-gpt1 の修正）

- ドラッグは始めたポインター（指）だけが持ちます。ほかの指が触れても動かず、ほかの指が離れても終わりません（`drag.pointerId`、`endDrag(e)`）。
- 「✋ ドラッグで動かす」がオフのときは、プレビューの上でも指で画面をスクロールできます（`#studioCanvas.locked{touch-action:pan-x pan-y}`）。
- Claude 側で1行足しました：終わりの知らせを取りこぼして、つかんだままになっていたら、次に触れたときに外します（`pointerdown` の先頭）。

## 6. 確かめていないこと・気になっているところ

- **iPhone の実機**：Safari での、指によるドラッグを試していません。テスト環境で指の操作を再現して、1本指で動かせることと、2本目の指に横取りされないことは確かめています。
- **OBS**：アプリと立ち絵のウインドウ（キャラクターだけ・透過）を、実際に取り込んだときの見え方を確かめていません。
- **歌枠管理シートとの連携（Apps Script）**：本物の Google 上では動かしていません。手元でスクリプトをまねて動かす試験だけです。
- **ボイス録り**：録った音声は、.live に入りません。
- **場面の画像**：準備中・離席中などに出す画像の位置は、映像の向きごとには分けていません。
- **「音のお品書き」の並べ方**：環境音と BGM の見せ方は、作者と相談中です。案は「ぽんと鳴らす音（効果音・ボイス）」と「流しておく音（環境音・BGM）」の2つにまとめることです。

## 7. 修正のあとに確かめてほしいこと

- **起動**：開いて、ブラウザのコンソールにエラーが出ないこと。
- **立ち絵とマスコットの位置**：立ち絵を登録して位置・大きさを変え、読み込み直しても同じ位置のままであること。
- **向きごとの記憶**：横・縦・3:4 を切り替えると、それぞれの向きで決めた立ち絵・マスコットの位置に戻ること。
- **画像を反転・変形させていないこと**：変更部分に `scale(` の負の値や、縦横で違う値がないこと。
- **.live**：書き出して、別のブラウザ（またはシークレットウインドウ）で読み込み、同じ状態に戻ること。
- **スマホ**：iPhone SE くらいの幅（375px）で、横にはみ出す欄がないこと。
