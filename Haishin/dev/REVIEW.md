# 配信処オトノハ／歌枠管理シート 点検記録

確認日：2026年10月30日（日本時間）

## 結論

添付HTMLには、修正の継ぎ足しによる読みづらさと、保存・録音開始終了・キャラクター補完の境界に具体的な問題がありました。ただし、旧版の互換処理や二つの音声出力経路を一律に不要と判断して削る段階ではありません。

修正版は、既存の機能と保存キーを維持しながら、確認できた問題を限定して直しています。単体で使うファイルはルートの `index.html`。`source/` は今後の編集用です。見た目の全面変更や配信サービスへの公開はしていません。

## 整理の範囲

- 元の3つのスクリプト境界を保ち、`theme.js`・`audio-studio.js`・`visual-studio.js`へ分離しました。CSSも二つのファイルに分けています。
- 関数・文・大きな設定オブジェクトに改行を入れました。整形の前後で構文木が一致することを確認しています。
- 単体HTMLは `build.py` から再生成できます。外部CDN・追加パッケージは使いません。
- これはES Modulesへの全面移行ではありません。元から共有されている変数・関数が残るため、スクリプトの順序は変更しないでください。
- 元の添付HTMLは `original/index-original.html` に同梱しています。

## 不要と断定せず残したもの

1. **旧形式の読み込み・旧タブ配置の移行処理**：過去の設定を失わないために必要です。利用中のバックアップ形式を確認してから段階的に廃止します。
2. **モニターと収録・送出の別経路**：自分が聴く音と出力する音を分けるための構成です。まとめると音量やミュートの意味が変わります。
3. **四枚式と一枚式の立ち絵**：異なる利用方法を支えているため維持します。
4. **通常プレビューと設定内プレビュー**：同じ映像を異なる操作場所で見るためのものです。描画の完全重複ではなくコピー表示です。

## 次に整理するとよい箇所

| 優先度 | 内容 | 判断 |
|---|---|---|
| 高 | 長時間の映像収録 | 動画を停止までメモリに保持する方式。今回の一覧削除は収録後の保持対策です。長尺収録中のメモリ増加は未解決で、逐次ファイル保存・容量表示などの別実装が必要です |
| 高 | バックアップ読込のロールバック | 音声用は複数の保存操作に分かれています。途中で容量不足になる場合まで含めた一括取り消しは未実装です |
| 中 | 保存処理の一元化 | localStorage・IndexedDBとUI更新を機能ごとに分け、保存失敗の返り値を呼び出し側まで返す構成にすると保守しやすくなります |
| 中 | 一覧とプレビューの再構築 | 名前入力などで画像URL・DOMを毎回作り直す処理があります。画像更新と文字更新を分けると負荷を減らせます |

| 低 | 企画モード・詳細設定 | 使わない機能は折りたたみを初期状態にする程度でよく、機能本体を削除する理由はまだありません |

## 歌枠管理シートの指摘

対象：https://docs.google.com/spreadsheets/d/12Yy__n0ObIdhvtC3YY9CwpoWkciJlwTXrV3YbFP87bo/edit

8タブの構成、見出し・入力例、配信ログの列配列数式と入力規則、概要欄の生成式を確認しました。シート本体は変更していません。全1000行のデータ監査・利用条件の再調査は実施していません。

### 優先して直す設計

1. **曲名・音源タイトルだけを検索キーにしない。** 配信ログI列などは音源B列のタイトルでVLOOKUPしています。同じタイトルでキー違い・購入版違いを登録すると区別できません。見せる名前はそのまま、内部に変更しないIDを隠し列として持たせる案が適切です。曲IDを画面に大きく出す必要はありません。
2. **選択した曲と音源の対応を照合する。** E列の曲とF列の音源は独立したプルダウンです。現在の確認範囲には「音源A列の曲と、選択中の曲が一致するか」の判定がありません。曲が異なる場合に警告する列を追加すると、別曲の音源条件・クレジットが混ざるのを防げます。
3. **配信先・収益化が空欄のときは要確認にする。** N列は配信先がYouTube以外なら一律にYouTube以外の値を参照し、O列は収益化が「あり」でなければ対象外になります。そのため空欄もその分岐に入ります。L・M列が未入力なら、最終P列も要確認にする設計が必要です。
4. **想定外の値を使用可にしない。** P列は不可・未確認・条件付き等の除外に当たらない値を使用可にする形です。「配信先の使用=可」かつ「収益化=可または対象外」を明示的に確認する方が、誤入力時の判定を限定できます。
5. **IRIAMと17LIVEを一つの欄で扱わない。** YouTube以外を一括判定すると、個別の利用先条件を表現しきれません。ここで各サービスの最新許諾状況を判定したわけではありません。データ構造上、配信先ごとに記録できるようにするという指摘です。

### 残すもの・表示を減らせるもの

- 提供者ごとの基本条件と音源ごとの個別条件は、基本値と例外なので両方残します。
- 管理団体に登録された元表記の控えは、表示名との照合用に残します。普段は列を非表示にできます。
- 自動計算列は非表示または保護し、配信ログの入力部分を左側にまとめると扱いやすくなります。
- 利用条件の「要点」と「原文」は用途が異なります。原文を消すより、折りたたみや非表示で見た目を整理する方がよい構成です。
- 概要欄の完成文とD列の1行1セル表示も、確認用とコピー用なので併存する理由があります。

## 検証

Node.js 24の構文解析と、修正箇所を切り出した10項目の回帰検証が通っています。元のコードでは、そのうち9項目で同じ期待結果を満たしませんでした。ファイル容量やメモリ負荷を測る性能試験ではありません。

HTMLには重複した静的IDがなく、外部CDN等のリソース参照も追加していません。生成した単体HTMLと編集用ソースのスクリプト内容を照合しています。

**未確認：** 実ブラウザの起動・画面の見た目、実マイク、音声録音、動画収録、OSの音声出力機器、OBS等での送出・長時間連続動作。本環境のブラウザーから作業用HTMLのサーバーに接続できなかったため、実機試験済みとは扱っていません。

## 使用・移行

1. 現在使っているアプリで、音声側 `.kissa` と映像側 `.json` の両方を書き出します。録音済みテイク・収録済み動画はそれぞれ別に書き出します。
2. 修正版の `index.html` を、これまで使っていたブラウザーで開きます。ファイルの場所や公開元が変わると保存済みデータが見えなくなる場合があります。見えない場合に備えるのが上記バックアップです。
3. 必要に応じて二つの設定を読み込み、短い試験収録で、ミュート・音量・映像の開始停止・書き出し結果を確認します。

既に失われた設定や、添付HTMLに含まれていないブラウザー内データを今回復元したという意味ではありません。
