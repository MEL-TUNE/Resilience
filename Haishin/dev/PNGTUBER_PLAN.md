# PNGTuber の動き（髪の揺れ・口・目）と、声付きの掛け合い：設計の控え

作成：2026年11月18日（STUDIO 0.11.5 の時点）
元になった依頼：作者が ChatGPT と相談して作った引き継ぎ文（髪の揺れを、まばたきのように「始まる時刻」と「再生の順番」に分けて扱う、など）。Claude が現行のコードと照らして精査した結果をここに置く。作者の判断待ちの点は最後にまとめる。

## 現行のコードで確かめたこと

| 部分 | 場所 | いまの作り |
| --- | --- | --- |

| 口パク | 60-frame.js | 口が開く音量（threshold）を超えたら開き、閉じるのは3dB下回ってから（ヒステリシス）。閉じるまでの時間（hold 40〜600ms）。口の動きは「開けたまま」か「パクパク（開閉の長さをランダム）」。音量をなめらかにした値（talkEnv）は体の動きに使っていて、口の開きの大きさには使っていない。歌うときの口パク（songTh、0.11.3）で、歌の間だけ口が開く音量を上げられる |

## 髪の揺れ：推奨は「支点方式を1パーツ」から

| | 差分を順に出す（3枚） | 支点で回す（1枚） |
| --- | --- | --- |
| 描く素材 | 待機・中間・最大の3枚（同じ位置で重ねて描く） | 動くパーツ1枚＋ベースの塗り足し |
| 低い fps（10〜15） | 1コマ66〜100ms。5コマの往復は0.3〜0.5秒になり、10fps では中間のコマが飛びやすい | 角度を時刻から毎フレーム計算するので、コマが飛んでも動きは連続 |
| 負荷 | 画像を切り替えるだけ（軽い） | 回転して1回描くだけ（軽い） |
| 表現 | 毛先の曲がり・線の変化まで描ける | 形は変わらない（回るだけ）。髪飾り・一房・リボン向き |
| 失敗しやすいところ | 中間のコマとの継ぎ目、クロスフェードすると線が二重 | 回ったときにベースの元の輪郭が見える（塗り足しで防ぐ） |

最初に入れる一案：支点方式。理由は、作者の運用（低スペック、10〜15fps の配信）で滑らかさが崩れにくいことと、操作を「パーツの画像・支点・揺れ幅」の3つに絞れること。差分方式は、支点方式の作りの上に「コマの列」を足す形で次の段に回す。

揺れのきっかけ：
- 体の動き：avatarPose の結果（頭の位置と傾き）の変化を、減衰するばね（角度・角速度）に入れる。ばねは「いまの揺れに力を足す」だけなので、同じ動作中に揺れが最初からやり直しにならない。
- 待機中の微かな揺れ：まばたきと同じく、始まる間隔だけをランダム（例：4〜9秒）にして、小さな力を一回入れる。
- 音量では揺らさない（BGM・効果音を鳴らす運用のため）。入れるとしても、マイクの音量だけ。

## 素材の作り方（自作の立ち絵1体・胸上・動くパーツ1つ）

1. ベース：動くパーツを外した立ち絵。パーツが回ったときに見える範囲（付け根のまわりと、揺れの外側）を塗り足す。
2. 動くパーツ：ベースと同じキャンバスの大きさで、パーツだけを透過 PNG に書き出す（位置合わせが要らない）。オトノハは読み込むときに透明な余白を切り、元の位置を覚える（メモリを使うのは切った後の大きさだけ）。
3. 目と口は、いまの4枠（または表情の2枚）をそのまま使う。

## 改修の順序（案）

PNGTuber
1. 揺れパーツ1つ（支点方式）：キャラクターごとに1つ。画像は IndexedDB（キー案：`キャラ:sway0`）、設定は state.chars[キャラ].sway＝{支点の x・y（元の画像の座標）、揺れ幅、戻りの速さ、待機中の揺れ}。設定画面の確認用の画面で付け根を押して支点を決める。描くのは drawAvatar の中、ベースの直後（同じ変形の中なので、配信用ウインドウ・アプリ表示・収録に同じ動きで出る）。次へ進む条件：10・15・30fps で同じ時間で揺れが収まる、継ぎ目が見えない、.live の書き出しと読み込みで残る。
2. 表情を出している間のまばたき（表情ごとの目閉じの差分）を足すかどうか。
3. 口の開きを2段（小・大）に：talkEnv を口の大きさにも使う。口の絵が1枚増える。
4. 差分方式（コマの列）。

AITuber（声付きで一往復）
1. いまできる確かめ：リオの短い台詞を録音（または合成）した音声ファイルを「音のお品書き」のボイスに入れて鳴らす。BGM・効果音と同じ通り道なので、OBS 向けの出力と内蔵の収録に入るかを、作者の環境で確かめられる。
2. 合成エンジン（AivisSpeech など）を呼ぶ：返事を1文ずつ声にし、声が鳴る時刻に字幕を出す。止めたら、まだ鳴っていない文は捨てる（読み上げの順番を一つの列にして、止めるときに列ごと消す）。
3. リオの口パク：声の通り道に付けた音量で、相方（マスコット、またはリオの立ち絵）の口を動かす。配信者の口パク（マイク）には入れない。
4. 押して話す音声入力（拾った区間だけ文字にして、直してから送る）。

現行の入口：掛け合い（準備の「AIキャラ・声」）は全部入りのページ（index.html）と配信用（obs.html）にあり、収録用（rec.html）にはない。内蔵の動画収録は全部入りと収録用にあり、配信用にはない。いまオトノハだけで「掛け合いを動画に収録する」なら全部入りのページ。配信用で OBS 側が録る形もある。

手元のAI：いまは stream:false（返事が全部できてから字幕になる）。最初の字幕までの時間を短くするなら、返事を流れで受け取る（stream）に変えて、1文できたら字幕の列に足す。
